# ربات ماری — معامله‌گر تمرینی

پیاده‌سازی رباتی که در سند `MARI_CORE_DOCTRINE_001.md` و بخش ۳۳ `mother-document.md` توصیف شده.

> **قفل دائمی: فقط خواندن داده | فقط تمرینی | بدون سفارش واقعی**
> در کل این بسته هیچ کلید صرافی، هیچ امضا و هیچ نشانی ثبت سفارش وجود ندارد.
> یک آزمون خودکار این را بررسی می‌کند. فقط داده‌های عمومی تووبیت خوانده می‌شوند.

## اجزا

| فایل | کار | بخش سند |
|---|---|---|
| `trend.py` | طبقه‌بند ۸حالته (A صعودی قوی تا H نامعلوم) با ترکیب ۶ عامل | دکترین ۳ |
| `position.py` | نگه‌داشتن برنده‌ها، حد ضرر متحرک، فروش پله‌ای ۵مرحله‌ای، برداشت جزئی سود | دکترین ۴ تا ۷ |
| `risk.py` | سقف ۵ موقعیت، ریسک ۱٪، سقف ۲۰٪ برای هر موقعیت، فاصلهٔ ۶ساعته، فیوز ۳ ضرر پیاپی، توقف با افت ۳٪ روزانه، فیلتر بیت‌کوین و نقدشوندگی | دکترین ۹ |
| `ledger.py` | دفتر شواهد فقط-افزودنی با زنجیرهٔ هش، شناسهٔ اجرا، هش تنظیمات و هش داده | دکترین ۱۰ و سند مادر ۳۴ |
| `data.py` | دریافت دادهٔ عمومی تووبیت و کنترل کیفیت (داده‌های تکراری، شکاف، کندل ناممکن، قیمت یخ‌زده) | سند مادر ۳۴ |
| `engine.py` | ترتیب کار: کشف، رتبه‌بندی، فیلتر. تصمیم روی کندل بسته گرفته می‌شود و اجرا در قیمت باز کندل بعد | سند مادر ۳۳.۵ |
| `backtest.py` | آزمون روی دادهٔ گذشته و محاسبهٔ شاخص‌ها: نرخ برد، ضریب سود، افت سرمایه، نسبت شکار سود، سود بازگردانده، بوت‌استرپ | دکترین ۱۱ و ۱۲ |
| `telegram.py` | گزارش فارسی و فرمان‌های `/start /report /trades /hunt /council /help /stop` | سند مادر ۳۳ |
| `live.py` | اجرای ساعتی با گشت در کل بازار: ۴۰ نماد پرحجم و ۶۰ نماد چرخشی | سند مادر ۳۳.۵ |

## اجرا (از پوشهٔ `scripts`)

```bash
# آزمون روی داده‌های موجود در مخزن (بدون اینترنت)
python3 -m mari_bot backtest

# یک چرخهٔ زنده با دادهٔ عمومی تووبیت
python3 -m mari_bot once

# اجرای پیوسته (هر ساعت) همراه با تلگرام
export MARI_TELEGRAM_TOKEN=...      # فقط در محیط؛ هرگز داخل فایل نگذارید
python3 -m mari_bot run

# گزارش وضعیت ذخیره‌شده
python3 -m mari_bot report

# بررسی سالم بودن دفتر شواهد
python3 -m mari_bot verify-ledger mari_bot/state/ledger.jsonl

# آزمون‌ها
python3 -m unittest discover -s mari_bot/tests -t .
```

وضعیت ربات در `mari_bot/state/` ذخیره می‌شود. این پوشه در گیت ثبت نمی‌شود.
در اولین اجرای زنده، ربات تاریخچهٔ گذشته را دوباره پخش نمی‌کند و فقط از آخرین کندل بسته شروع می‌کند. این کار جلوی ثبت معاملهٔ ساختگی از گذشته را می‌گیرد.

## قانون فروش (خلاصه)

| وضعیت روند | اقدام |
|---|---|
| A یا B (صعودی) | نگه‌داشتن موقعیت بدون حد سود ثابت. حد ضرر متحرک ۳ATR (در A) یا ۲٫۵ATR (در B) |
| رسیدن سود به ۱٫۵R | انتقال حد ضرر به نقطهٔ ورود |
| رسیدن سود به ۳R در وضعیت B | فروش ۲۵٪ (در A فروخته نمی‌شود تا برنده زود از دست نرود) |
| C (ضعیف‌شدن) | هشدار. اگر ۳ کندل پیاپی ادامه پیدا کند یا وضعیت D شود: فروش یک‌سوم |
| E (نزولی) | فروش نیمی از باقی‌مانده |
| F یا خوردن حد ضرر | خروج کامل (ابطال فرضیه) |
| G (سقوط) | خروج اضطراری |
| ۷۲ ساعت بدون حرکت | خروج زمانی |

## نتیجهٔ صادقانهٔ آزمون فعلی

روی ۶۷ نماد با حدود ۲۱ روز دادهٔ ساعتی (`mari_megatrend/data`) و کارمزد فرضی ۰٫۱٪ و لغزش ۰٫۰۵٪ در هر طرف:

- ۳۲ معامله
- نرخ برد ۲۱٫۹٪
- ضریب سود ۰٫۳۶
- بازده خالص ۷٫۱٪ منفی
- بیشترین افت سرمایه ۷٫۷٪
- بازهٔ اطمینان ۹۵٪ میانگین بازده هر معامله: از ۲٫۸٪ منفی تا ۰٫۴٪ منفی

یعنی **با این تنظیمات و روی این بازهٔ کوتاه، ربات سودده نیست.**
پارامترها عمداً برای بهتر شدن نتیجه روی همین داده تنظیم نشدند، چون سند (بخش ۳۵.۵) چنین بیش‌برازشی را ممنوع کرده.
قدم بعدی دریافت دادهٔ طولانی‌تر است، بعد آزمون خارج از نمونه، و فقط پس از آن تنظیم پارامترها.
